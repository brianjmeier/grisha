— Grisha

Grisha is a command-line tool that marks a coding agent's work. For each task the agent writes a sheet: what must be true when the work is finished, and the command that checks each claim. You approve the sheet. Grisha runs the checks itself, so the agent never marks its own work. Its rules keep the lines you ban out of new code.

$ npm install -g @brianmeier/grisha Source on GitHub

by grisha gate, in a commit hook

The gate exits 1 while a check is failing or out of date, or a rule is broken. Asked for proof, it also refuses until every claim is settled. Call it from a commit hook, a push hook, or your agent app's own hook.

keeps old-code-left-alone: A rule blocks the lines a branch adds. Older lines are counted, not blocked.

by grisha rules, with no agent and no task

A rule is a pattern that lines of code may not match: a comment, a skipped test, a mock. You can turn one on in an old codebase today. The count is what is left to clean up, and when it reaches none the rule can block every line.

$ grisha rules
src/billing.ts:1  no-comments
  + // TODO: bill unread rows only
  Delete the comment. If it explains a workaround, fix what it works around; if it states a constraint, turn the constraint into a type, a test or a check.

Each rule, the lines it blocks, and the lines already in the code that match it:
  no-comments             added lines  1 line in 1 file
  no-effects              added lines  none
  no-timers               added lines  none
  no-suppressions         added lines  none
…
`grisha rules <rule>` lists every line a rule matches.
