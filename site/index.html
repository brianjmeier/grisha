grisha

Your agent says the work is done. Grisha makes it show that.

A command-line tool for work done by coding agents. The agent writes down what must be true when a task is finished, and the command that checks each claim. You approve the list, and Grisha runs the checks itself. Its rules keep the lines you ban out of new code.

$ npm install -g @brianmeier/grisha

runs on Bun. Then grisha rules --init once, and tell your agent to “use grisha”, in Claude Code or any agent CLI

You approve the plan. Nothing is run before your yes.

The agent writes what must be true when the work is finished, and the command that checks each claim. Your agent app shows you the plan and asks. If the plan changes later, you are asked again.

A check has to fail before it counts.

A check that passes before the change and after it has shown nothing. Grisha has the agent break the code, see the check fail, and restore it. When the code a check covers changes, the check is out of date and has to run again. Put grisha gate in a commit hook and unfinished work stops there.

Rules for the lines a branch adds. Old code is counted, not blocked.

A rule is a pattern that lines of code may not match: a comment, a skipped test, a mock. Turn one on in an old codebase today. The count of older lines is what is left to clean up, and when it reaches none the rule can block every line.

No quiet changes.

An agent that cannot meet a rule may turn the rule off. Grisha sees that the rules are not the ones you approved, and the gate refuses until you have seen the change and said yes.

The proof goes in the pull request.

Every claim, the command that checked it and where it stands. What no command can settle is listed for you to read, and so is every file changed outside the plan.

“Done, tests pass” is a claim. Grisha keeps the evidence, and nothing is added to your repository.
