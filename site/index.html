Abstract

Done, tests pass. Grisha: Show your work.

Grisha is a command-line tool that makes a coding agent show that its work is done, instead of saying so. The agent writes down what must be true and the command that checks each claim, you approve that list, and Grisha runs the checks. A claim is proven only when its check has failed once and passes now. Rules keep unwanted lines out of the code a branch adds.

1Setup

  1. Install it. Grisha runs on Bun, so install that first. npm install -g @brianmeier/grisha
  2. Write the starter rules. grisha rules --init
  3. Try the rules in any git checkout. They need no agent and no task. grisha rules
  4. Link the skills into the folder your agent reads skills from. for skill in "$(npm root -g)"/@brianmeier/grisha/skills/*/; do ln -s "$skill" ~/.claude/skills/; done
  5. Give your agent a task and tell it to “use grisha”.
  6. Put the gate in a commit hook, and unfinished work stops there. grisha gate

Plans, rules and results live in ~/.grisha/, outside your checkouts, so nothing is added to the codebase.

2Rules

A rule is a pattern that lines of code may not match: a comment, a skipped test, a mock. It blocks the lines a branch adds and only counts the lines already there, so you can turn it on in an old codebase today.

$ grisha rules --init
Starter rules written to ~/.grisha/rules.json. They apply in every repository.

There are fifteen starter rules. Here a branch adds a comment to src/billing.ts. An older file already has one, which is counted and not blocked.

$ grisha rules
src/billing.ts:1  no-comments
  + // TODO: bill unread rows only
  Delete the comment. If it explains a workaround, fix what it works around; if it states a constraint, turn the constraint into a type, a test or a check.

Each rule, the lines it blocks, and the lines already in the code that match it:
  no-comments             added lines  1 line in 1 file
  no-effects              added lines  none
  no-timers               added lines  none
…
Rules are read from these files. A later file adds rules, replaces one by name, or turns one off:
  every repository            ~/.grisha/rules.json
  this repository, committed  ~/code/shop/.grisha/rules.json  (no file)
  this repository, only you   ~/.grisha/repos/shop/rules.json  (no file)
…
(exit 1)

A rule’s blocks says which matching lines are refused. Left out, it is "added lines", and the count of older lines is what is left to clean up. When the count reaches none, move the rule to "every line".

Table 1: What blocks does to a matching line.
blocksA line the branch addsA line already there
"added lines"blockedcounted
"every line"blockedblocked
"nothing"listedcounted

A rule is a name, a pattern tried on one line at a time, the files it applies to and the fix to name. This file adds a rule for a repository’s tests and turns a starter rule off.

{ "files": { "tests": ["**/*.test.ts", "e2e/**"] }, "rules": [ { "name": "no-act", "pattern": "\\bact\\(", "files": "tests", "blocks": "every line", "fix": "Wait for what the user sees." }, { "name": "no-casts-in-tests", "off": true } ] }

The rules cannot change quietly. Here the agent turned a rule off for itself, and the gate refuses until you have seen the change and said yes.

$ grisha gate
Before this goes further:
- The rules here are not the ones the person approved:
  no longer in force: no-comments
  Run `grisha rules --approve`: the person is shown what changed and asked.
(exit 1)
